# Managed search and visual similarity options (researched 2026-10-15)

## Which paid services are plausible for catalog text search and ranking?

### Takeaway
Algolia, Typesense Cloud, and Meilisearch Cloud are the most direct managed replacements for a small product-catalog search API. Elastic Cloud, AWS OpenSearch, and Google AI Commerce Search offer broader capabilities but add configuration, cost dimensions, or commerce-data requirements; benchmark them only if simpler options fail the relevance or scale target.

### Cited Findings
- **Algolia:** Grow provides keyword search, browse, query suggestions, manual synonyms, and rules; Grow Plus adds AI ranking and synonyms; NeuralSearch is listed under the custom-priced annual Elevate tier. Current free tier includes 10,000 search requests per month and 50,000 records; paid Grow/Grow Plus charge for requests and records over included amounts. One search-as-you-type keystroke can incur a search request. [Pricing and feature grid](https://www.algolia.com/pricing). Algolia's own image-search use case describes sending uploaded images to a third-party recognition service and converting recognized attributes into Algolia queries, so image recognition is not inherent to its ordinary keyword index. [Image search use case](https://www.algolia.com/use-cases/image-search).
- **Typesense Cloud:** Dedicated clusters are priced by provisioned RAM/CPU and bandwidth, with no per-record or per-search charge; the cluster fee continues while running regardless of traffic. [Cloud pricing](https://cloud.typesense.org/pricing/calculator), [billing documentation](https://cloud-help.typesense.org/article/billing-process). Typesense supports typo-tolerant text search, filtering, vector search, and hybrid lexical/vector search. [Search API](https://typesense.org/docs/28.0/api/search.html), [vector and hybrid search](https://typesense.org/docs/latest/api/vector-search.html). Its scoped search keys can enforce document/field filters, but the admin key must stay off the client. [Access-control guide](https://typesense.org/docs/guide/data-access-control.html).
- **Meilisearch Cloud:** Cloud offers usage-based or resource-based billing, with a published starting price and a 14-day trial; self-hosted Meilisearch is MIT-licensed. [Pricing](https://www.meilisearch.com/pricing). Its hybrid product combines text and semantic search and may use managed or third-party embeddings. [Hybrid search](https://www.meilisearch.com/products/hybrid-search); custom/user-provided embeddings are described by Meilisearch. [Hybrid design note](https://www.meilisearch.com/blog/fixing-hybrid-search).
- **Elastic Cloud:** Hosted Elastic charges for provisioned resources; serverless is usage-based. Elastic offers full-text, vector search, filters, and hybrid ranking, including reciprocal rank fusion. [Pricing/deployment models](https://www.elastic.co/pricing), [cloud feature matrix](https://www.elastic.co/subscriptions/cloud/). Its vector-database serverless bill includes stored GB, reserved search capacity, ingested GB, and a recurring project infrastructure fee; search billing has a 16 GB active-storage minimum and continues while the project exists. [Vector billing dimensions](https://www.elastic.co/docs/deploy-manage/cloud-organization/billing/vector-database-billing-dimensions).
- **AWS OpenSearch Service:** Managed domains charge instance hours, attached storage, and transfer; Serverless charges OpenSearch Compute Units and storage. [AWS pricing](https://aws.amazon.com/opensearch-service/pricing/). OpenSearch supports image-derived vectors, cosine similarity, and nearest-neighbor search, but image embedding generation requires a model or integration outside the index itself. [Vector search guide](https://docs.aws.amazon.com/opensearch-service/latest/developerguide/vector-search.html).
- **Google AI Commerce Search:** Product search/browse calls are billed per request; catalog and event ingestion are free according to its pricing page. [Pricing](https://cloud.google.com/products/retail/pricing). It expects both product catalog records and user events for ML search/recommendations and offers product hierarchy, expansion, filters, and personalized results. [Features](https://docs.cloud.google.com/gemini-enterprise-cx/ai-commerce-search/features). Documentation says integration commonly takes weeks and warns against sharing cached personalized results between users. [Implementation overview](https://docs.cloud.google.com/gemini-enterprise-cx/ai-commerce-search/overview?hl=en).

### Inferences
- For issue #178's small reproducible comparison, Algolia Grow, Typesense Cloud, and Meilisearch Cloud are reasonable managed text-search candidates; run the same frozen corpus and query labels against each. A dedicated Typesense cluster creates an idle-cost floor, while Algolia's request meter makes typeahead behavior part of the estimate. These are cost-model tradeoffs, not an estimated Dressed bill.
- Elastic/OpenSearch would be justified if Dressed needs a single engine for sophisticated lexical plus vector retrieval and has the operational capacity to tune it. Google AI Commerce Search's event and optimization model fits an actual retailer better than a prototype catalog with no first-party commerce outcomes.

### Gaps
- No fair monthly quote can be computed without the expected record count, average indexed size, regions, monthly searches/typeahead policy, image count, and uptime target. Current prices and plan limits should be rechecked before procurement.
- The public docs do not prove any vendor's ranking beats the current baseline on Dressed's catalog; the labeled evaluation in issue #178 must decide that.

## Which managed services support image-to-product similarity?

### Takeaway
Google Vision API Product Search is a direct managed image-to-catalog match service for apparel. Vector databases can retrieve similar images but need an embedding pipeline and carefully scoped catalog; similarity scores do not establish exact product identity.

### Cited Findings
- **Google Vision API Product Search:** Supports an `apparel` category and returns visually and semantically similar products from a retailer-provided product set/reference images. [Product Search overview](https://docs.cloud.google.com/vision/product-search/docs?hl=en). Query image can be a Google Cloud Storage URI, web URL, or base64 data. [Search guide](https://docs.cloud.google.com/vision/product-search/docs/searching?hl=en). Pricing is metered by prediction queries and indexed-image storage, with the first 1,000 image units in each schedule free. [Pricing](https://cloud.google.com/vision/product-search/pricing). Google warns scores are comparable within a query but not calibrated across different queries, so one global match threshold is unsuitable. [General tips](https://docs.cloud.google.com/vision/product-search/docs/general-tips).
- **Pinecone:** Managed vector store offers dense, sparse, and full-text indexes; pricing meters storage/read/write units and has plan minimums beyond Starter. [Pricing](https://www.pinecone.io/pricing/). This is an index for vectors, not a ready-made product-photo recognition pipeline; image preprocessing, embedding model, catalog metadata, and freshness remain application work. The latter sentence is an architectural inference from the database's published index and inference offerings. [Pricing/feature table](https://www.pinecone.io/pricing/).
- **Weaviate Cloud:** Managed service uses the open-source Weaviate engine and now bills by vector dimensions, object storage, and backups with plan minimums. [Pricing](https://weaviate.io/pricing). Weaviate supports image queries (`nearImage`) when the collection has an appropriate multimodal vectorizer. [Multimedia search guide](https://docs.weaviate.io/weaviate/search/near-media).
- **Typesense/Elastic/AWS OpenSearch:** Each supports vector retrieval; Typesense documents hybrid keyword/vector queries and AWS explicitly lists image search as a vector use case. They still require a chosen image embedding model and a catalog of indexed product images. [Typesense vectors](https://typesense.org/docs/latest/api/vector-search.html), [Elastic search features](https://www.elastic.co/subscriptions/cloud/), [AWS vector search](https://docs.aws.amazon.com/opensearch-service/latest/developerguide/vector-search.html).
- **Google AI Commerce Search:** Google describes discovery through text and images in guided commerce search, but its published API and catalog docs center on retail catalog plus user-event integration; do not equate it with the separate Vision API Product Search photo query without a focused proof of concept. [Product overview](https://docs.cloud.google.com/retail/docs/what-is-it), [API reference](https://docs.cloud.google.com/gemini-enterprise-cx/ai-commerce-search/reference/rest), [Vision Product Search overview](https://docs.cloud.google.com/vision/product-search/docs?hl=en).

### Inferences
- Test image matching as a separate second-stage experiment: `photo -> item crop/manual category -> embedding or Vision Product Search -> candidates -> availability/provenance filter -> similar results`. Maintain retailer IDs/URLs outside the similarity score. Only call an item exact after a verified source identifier establishes identity.
- For a 30–50 item benchmark, an external vector store is likely unnecessary. Brute-force cosine similarity over a fixed embedding array can establish whether embeddings add relevance before committing to a vendor or recurring cost.

### Gaps
- Image rights and permission to upload source/user photos to a vendor must be checked for the actual data sources and privacy policy.
- No benchmark has established whether Vision Product Search, a multimodal embedding model, or simple category/attribute text search performs best on Dressed photos.

## What implementation and privacy controls should the proposal specify?

### Takeaway
Keep the catalog database authoritative and treat any search service as a rebuildable index. Push only approved public product fields to the provider; keep private closet photos and user identity out of the search index, and enforce availability/freshness in the server response.

### Cited Findings
- Algolia documentation describes importing/synchronizing source records into its index and separately controlling search versus write API permissions. [Index synchronization](https://www.algolia.com/doc/indexing/import-synchronize-data). Typesense explicitly warns not to put admin keys in a frontend and supports collection/document/field restrictions with scoped keys. [Access-control guide](https://typesense.org/docs/guide/data-access-control.html).
- Google AI Commerce Search documentation says the service processes catalog and user-event data on the customer's behalf and places responsibility for lawful collection on the customer. [Features and data requirements](https://docs.cloud.google.com/gemini-enterprise-cx/ai-commerce-search/features). Google also warns not to cache personalized results across users. [Implementation overview](https://docs.cloud.google.com/gemini-enterprise-cx/ai-commerce-search/overview?hl=en).
- Provider plans have region, security, and support differences: Algolia Grow lists US/UK/EU locations while Elevate advertises enterprise security/support; Typesense lists selectable deployment regions and separate support plans; Weaviate pricing varies by region and plan. [Algolia plans](https://www.algolia.com/pricing), [Typesense cloud calculator](https://cloud.typesense.org/pricing/calculator), [Weaviate pricing](https://weaviate.io/pricing).

### Inferences
- Minimal backend adapter: normalize an approved public `CatalogProduct` document; upsert/delete by stable product ID after catalog changes; store source, retailer URL, availability, `lastCheckedAt`, category and searchable title/brand/attributes; reindex from authoritative storage. Search adapter returns IDs plus scores; backend hydrates/verifies current records, drops unavailable/stale products, applies deterministic tie-breaking, and returns pagination plus `matchReason` and source timestamp. Compare adapters offline against the same query/relevance fixture before switching production traffic.
- Do not index raw private closet images, user-uploaded photos, owner IDs, or event histories as part of a public-catalog pilot. If visual search later needs uploads, use short-lived processing, explicit retention/deletion behavior, server-held credentials, and a documented vendor data-processing review.
- Cost comparison worksheet should include catalog records/images, bytes per item, queries and keystrokes per session, embedding calls on catalog changes and user queries, region, HA/SLA tier, egress, and always-on cluster minimum. Run a small load test before choosing serverless versus provisioned pricing.

### Gaps
- Dressed's current deployment region, provider contracts, authorized product image sources, and production usage forecasts are not established in these vendor documents; do not infer them.
- Vendor security claims and plan-specific controls need review against the chosen contract and deployment, particularly if any personal data or private photos are sent.
