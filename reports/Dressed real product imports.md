# Bring real retailer products into Dressed

**Build a hybrid: shared links for broad capture, on-demand search for discovery, and approved feeds for a durable catalog.** No verified provider supplies every Pacsun, Depop, and eBay product with unrestricted access and reuse. Those sources require different integrations, but they can share Dressed's review and normalization flow. Start a small shopping-search experiment while pursuing Pacsun's Impact program and eBay production access. Let people contribute links, original annotations, and seller-authorized inventory to fill useful gaps. Background agents can expand searches and classify results, while source connectors supply the actual product facts. This recommendation assumes the first objective is finding real products inside Dressed; importing a link already in someone's hand is a smaller, immediately useful slice.

Research checked November 16, 2026. This is an acquisition recommendation, not an implemented integration or a measured provider benchmark.

## Separate four experiences before choosing an API

**Saving a product link, searching live offers, maintaining a catalog, and matching a photo are different jobs.** A saved link can remain useful with a user-written name and category. Live search needs relevant results and working purchase destinations. A persistent catalog additionally needs stable identities, refresh and deletion behavior, and permission for its display and storage. Photo matching needs a usable reference corpus and an evaluation of retrieval quality; it does not acquire that corpus by itself.

Dressed already has two useful starting points: pasted/shared HTTPS links reach editable review and an explicitly confirmed local Wishlist; a separate SQLite importer and read-only HTTP API support Discovery Search using synthetic data. A saved-response eBay adapter exists, but it makes no network requests. These are documented prototypes, not evidence of a live retailer connection. ([Local catalog](../backend/catalog/README.md), [current architecture](../docs/architecture.md))

Extend link import with this proposed order: approved source lookup, permitted Product/Offer JSON-LD extraction, basic Open Graph preview, then manual details. Structured product markup can contain identifiers, images and offer fields; Open Graph provides basic preview metadata but does not establish a selected size, price or availability. Preserve missing fields instead of asking an LLM to invent them. Retain the user's original link and review even when enrichment fails. ([Product schema](https://schema.org/Product), [Open Graph](https://ogp.me/))

## Pacsun, eBay and Depop need distinct connectors

**Pacsun's current official affiliate route is Impact.** Its footer links to the PacSun Impact application. Impact lets approved partners retrieve catalogs through portal downloads, FTP or API, but the brand must supply a catalog and grant access. Pacsun-specific feed availability was not verified. Ask specifically for product IDs, URLs, images, variants, price, stock, refresh cadence, native-app display, storage and eventual image-indexing rights. An approved downloaded feed is enough for the first import; automated API transport can follow. ([Pacsun footer](https://www.pacsun.com/content/site-map.html), [Impact catalog access](https://help.impact.com/partner/what-would-you-like-to-learn-about/platform-features/marketing-content/product-marketplace-and-catalogs/download-product-catalogs-as-a-partner))

**eBay has the strongest documented marketplace discovery API of the named sources, conditional on approval.** Browse supports keyword, category, identifier and image searches plus item detail. Production Buy API access requires review and agreements; its default Browse allowance is 5,000 calls per day. Reuse Dressed's adapter after approval, adding backend authentication and bounded searches. ([Browse](https://developer.ebay.com/develop/api/buy/browse_api), [production requirements](https://developer.ebay.com/api-docs/buy/buy-requirements.html), [limits](https://developer.ebay.com/develop/api/buy/api_call_limits))

eBay also affects the product design: its API license requires publicly displayed eBay content to be visually isolated from other listings, displayed listing information to be no more than six hours behind the source, and unavailable public content to be removed. Use an eBay section with a small refreshed cache rather than assuming a permanently mixed product grid is allowed. Missing results from one query do not prove that an item sold. ([API license, section 8](https://developer.ebay.com/develop/api-license-agreement))

**Depop's documented API is private and seller-oriented.** Its product-list endpoint concerns a connected seller's inventory, not unrestricted marketplace search. No official public buyer-search API was found. The currently applicable October 2026 terms prohibit scraping/crawling and unauthorized content reuse. Initial support should therefore save a user-supplied link and original annotations; richer integration needs a partnership or participating sellers with appropriate permissions. Buying a scraper service does not establish those permissions. ([Depop overview](https://partnerapi.depop.com/api-docs/), [reference](https://partnerapi.depop.com/api-docs/reference/), [current terms](https://depophelp.zendesk.com/hc/en-gb/articles/360001773148-Terms-of-Service))

For broader retail coverage, qualify Awin feeds by actual accessible merchants. Its feed list exposes product counts and update times for eligible advertisers. Skimlinks is another option, but its Product Keys currently require Managed accounts; ordinary Growth access is insufficient. Neither source was verified to supply Pacsun or Depop to Dressed. A cooperating boutique's CSV or Shopify integration is a more controllable first source when large-brand approval is slow. ([Awin feeds](https://help.awin.com/developers/docs/downloading-a-list-of-your-product-feeds), [Skimlinks eligibility](https://support.skimlinks.com/hc/en-us/articles/26619916595869-What-is-a-Product-Key-and-do-I-need-one), [Shopify Storefront](https://shopify.dev/docs/storefronts/headless/building-with-the-storefront-api))

## Search and crowdsourcing provide useful breadth

**Use one shopping-search provider to measure coverage before building many connectors.** SerpApi documents Google Shopping results containing titles, merchant names, prices and thumbnails. Its examples often return Google Shopping product URLs, so resolving a direct merchant offer can require another endpoint. That extra request and its reliability belong in the experiment. Current published pricing is 250 free searches monthly or $25 for 1,000; SearchApi offers 100 free requests and a $40 tier for 10,000 searches. These are vendor request prices, not complete operating costs. ([Shopping results](https://serpapi.com/shopping-results), [offer details](https://serpapi.com/google-immersive-product-api), [SerpApi pricing](https://serpapi.com/pricing), [SearchApi pricing](https://www.searchapi.io/pricing))

Search retrieval does not automatically authorize a permanent public image database. SearchApi explicitly places third-party content permissions on its customer and excludes downstream storage and redistribution from its collection guarantee. Evaluate display and retention scope alongside result quality. No live calls were made in this research, so named-retailer coverage and usable-result rates remain unmeasured. ([SearchApi terms](https://www.searchapi.io/legal/terms))

Crowdsourcing should collect favorite product links, original style tags, corrections and explicitly contributed media. An illustrative seed effort of 20 volunteers contributing 15 links yields at most 300 candidates before deduplication. Keep private Wishlist saves separate from optional public contributions. For reusable inventory and images, recruit a few sellers or stores to supply their own CSV and media with agreed display terms. A contributor cannot necessarily authorize reuse of another seller's photographs.

Passive agents fit a bounded job such as “find new baggy jeans under this budget from supported sources.” They can generate query variations, classify evidence-backed results, detect duplicates and flag broken parsers. Source responses must supply prices, stock, identifiers and URLs. Twenty daily searches total 600 monthly base requests; five detail calls per search increase that to 3,600 before retries or model costs. This arithmetic favors targeted searches and feed-based bulk updates over continuous autonomous browsing.

## Prove one real discovery loop before expanding

The recommended first spike is **20 representative shopping queries plus 30 supplied product links**, spanning Pacsun, Depop, eBay and a few other relevant stores. Use one search provider; compare exact model queries, broad categories and style phrases. Record merchant coverage, direct purchase-link success, variant accuracy, evidence for price, image availability, latency and requests per usable result. For unsupported link enrichment, explicitly test the manual fallback. These are proposed evaluation samples, not completed tests or promised coverage.

The successful end-to-end result is a real product found or supplied, opened at its verified destination, reviewed by the user and saved once to Wishlist. Repeat the import to check identity handling; refresh a changed or unavailable listing; ensure a failed request does not falsely mark unrelated offers unavailable. Keep catalog offers separate from owned `ClothingItem` records. Review source configuration and URL-fetch restrictions before accepting arbitrary backend fetches, and retain provenance and observation time per field.

Pursue Pacsun feed access and eBay production approval alongside that experiment without making either a prerequisite for evaluating demand. If durable catalog access arrives first through a cooperating store, use it. The valuable early asset is a measured set of sources Dressed can reliably show and refresh. Broad link capture can grow immediately around that core; stronger public catalog and visual-matching promises should grow only with demonstrated coverage and permitted use.
