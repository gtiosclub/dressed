# Separate garments first, then match products

**Dressed needs two systems:** one to locate individual garments in an outfit photo and another to search a permitted retailer catalog for each garment. Open-source models can supply both stages, and paid APIs can shorten a pilot, but none of the documented options identifies any retail SKU from an arbitrary photo with guaranteed accuracy or universal catalog coverage. For a prototype, compare a text-prompted garment segmenter with a simple paid object-localization baseline, let the user correct its candidates, then search a small authorized product catalog with image embeddings. Call visually retrieved results **similar products**. Reserve **exact match** for a retailer product ID, source URL, GTIN, or other corroborating identity evidence; Google's own Product Search scores are not calibrated across queries. ([Google Product Search](https://docs.cloud.google.com/vision/product-search/docs?hl=en); [Google scoring guidance](https://docs.cloud.google.com/vision/product-search/docs/general-tips); [GS1 identifiers](https://ref.gs1.org/standards/genspecs/24.0.0/))

## Garment detection produces candidates, not product identities

Dressed's current whole-image classification cannot separate a coat, shirt, trousers, and shoes. Apple Vision can run a custom Core ML object detector to return individual object boxes, but that requires labeled detection training data. A box is enough to present selectable candidates; pixel masks become useful if Dressed needs clean cutouts or more precise product crops. ([Apple Vision classification](https://developer.apple.com/documentation/CoreML/classifying-images-with-vision-and-core-ml); [Apple object detection](https://developer.apple.com/documentation/vision/recognizing-objects-in-live-capture); [Apple training data](https://developer.apple.com/documentation/createml/building-an-object-detector-data-source))

For an **open-source server prototype**, Grounding DINO can find boxes from text prompts and SAM 2 can turn boxes into masks; both have Apache-2.0 code and checkpoints. SAM 3 combines text-prompted detection and masks, but its checkpoint access and custom SAM License deserve review before a commercial deployment. For a **smaller production model**, RF-DETR offers detection and segmentation with Apache-2.0 Nano-through-Large weights and experimental Core ML export; Ultralytics YOLO also exports to Core ML but uses AGPL-3.0 or an Enterprise license. None has published accuracy for Dressed's outfit and share-source photos. ([Grounding DINO](https://github.com/IDEA-Research/GroundingDINO); [SAM 2](https://github.com/facebookresearch/sam2); [Grounded SAM 2](https://github.com/IDEA-Research/Grounded-SAM-2); [SAM 3 and license](https://github.com/facebookresearch/sam3); [RF-DETR](https://github.com/roboflow/rf-detr); [Ultralytics licensing](https://docs.ultralytics.com/models/yolo11/))

**Paid baselines are cheap, but generic.** Google Cloud Vision Object Localization returns names and boxes at $2.25 per 1,000 images after the first 1,000 free units each month; AWS Rekognition DetectLabels returns labels and boxes for common objects, with its pricing example at $0.001 per image for the first million. Neither documents a promise to separate layered garments or return masks. Roboflow can host a custom detector or segmenter; its public plans start with a free tier and Core from $39 per month, but the selected model's rate and data terms must be checked. ([Google object localization](https://docs.cloud.google.com/vision/docs/object-localizer); [Google pricing](https://cloud.google.com/vision/pricing); [AWS DetectLabels](https://docs.aws.amazon.com/rekognition/latest/dg/labels-detect-labels-image.html); [AWS pricing](https://aws.amazon.com/rekognition/pricing/); [Roboflow pricing](https://roboflow.com/pricing))

## Product matching depends on catalog rights and coverage

**Open source:** crop each approved garment, embed it with FashionCLIP and a general comparator such as OpenCLIP or SigLIP 2, and rank images from a catalog Dressed is allowed to index. FAISS provides a local nearest-neighbor benchmark; Qdrant adds filtering and hosted operation when the catalog becomes live. FashionCLIP was fine-tuned on clean Farfetch product images, so its advantage on candid, occluded outfit crops is a hypothesis to test, not an established result. The model and index do not supply retailer listings, rights, prices, stock, variants, or stable product IDs. ([FashionCLIP model card](https://huggingface.co/patrickjohncyh/fashion-clip); [OpenCLIP](https://github.com/mlfoundations/open_clip); [SigLIP 2](https://github.com/google-research/big_vision/blob/main/big_vision/configs/proj/image_text/README_siglip2.md); [FAISS](https://github.com/facebookresearch/faiss); [Qdrant filtering](https://qdrant.tech/documentation/search-patterns/vector-search-filtering/))

**Paid:** Google Vision Product Search can detect multiple products and search a product set that Dressed uploads; prediction is free for the first 1,000 images monthly and $4.50 per 1,000 in the next tier, plus catalog-image storage and other cloud costs. Syte describes multi-object detection followed by similar offers from a merchant's catalog; ViSenze documents visual search against a catalog. Both are relevant vendor demos if Dressed obtains a usable retailer feed, but neither publishes a dependable self-service price or a guarantee of exact SKU identification for Dressed. Google Web Detection can find pages containing visually matching images, but those pages are leads to verify, not a product-identity database. ([Google Product Search](https://docs.cloud.google.com/vision/product-search/docs?hl=en); [Google Product Search pricing](https://cloud.google.com/vision/product-search/pricing); [Syte API](https://developers.syte.ai/); [ViSenze SDK](https://github.com/visenze/visearch-sdk-java/blob/master/docs/product-search-api.md); [Google Web Detection](https://docs.cloud.google.com/vision/docs/detecting-web))

| Option | Role in Dressed | Cost and constraint |
| --- | --- | --- |
| Grounding DINO + SAM 2, or SAM 3 | Multi-garment box/mask experiment | Self-hosting compute; SAM 3 has a distinct license and gated checkpoints. ([Repositories](https://github.com/IDEA-Research/Grounded-SAM-2), [SAM 3](https://github.com/facebookresearch/sam3)) |
| RF-DETR or YOLO | Train a compact detector after collecting labels | RF-DETR's standard weights are Apache-2.0; YOLO needs AGPL compliance or Enterprise terms. ([RF-DETR](https://github.com/roboflow/rf-detr), [YOLO](https://docs.ultralytics.com/models/yolo11/)) |

| FashionCLIP/OpenCLIP + FAISS | Local similarity ranking over licensed listings | Infrastructure and catalog acquisition; no built-in SKU proof. ([FashionCLIP](https://huggingface.co/patrickjohncyh/fashion-clip), [FAISS](https://github.com/facebookresearch/faiss)) |
| Google Product Search | Managed catalog search baseline | $4.50 per 1,000 paid-tier queries plus image storage; Dressed supplies the catalog. ([Pricing](https://cloud.google.com/vision/product-search/pricing)) |

## Pilot one review flow before selecting a vendor

**Stage 1: build a consented evaluation set** with full outfits, flat lays, social screenshots, overlapping layers, shoes, bags, and retailer imagery. Mark each visible garment, its acceptable crop, and any *known* matching product ID. Use this to measure detection recall, user correction rate, top-five relevant product recall, verified exact-SKU hits, false exact claims, latency, and cost per reviewed image. DeepFashion2 is a useful research reference for separate detection and consumer-to-shop retrieval tasks, but its maintainer describes non-commercial use; Fashionpedia's annotation license does not grant uniform rights to its source photos. Dressed should use images and catalog entries with explicit rights for commercial training and evaluation. ([DeepFashion2](https://github.com/switchablenorms/DeepFashion2); [DeepFashion2 licensing discussion](https://github.com/switchablenorms/DeepFashion2/issues/3); [Fashionpedia licensing](https://fashionpedia.github.io/home/data_license.html))

**Stage 2: run two detector baselines on the same images:** Grounding DINO + SAM 2 (or SAM 3 after license review) and Google Object Localization. Keep Dressed's review screen in control: users select candidates, correct categories, and manually add missed pieces. For search, start with a small permissioned catalog and compare FashionCLIP/OpenCLIP + FAISS with Google Product Search using the same garment crops. If detection quality is adequate but server cost or privacy is poor, train an RF-DETR or Core ML detector on corrected examples. Consider Syte or ViSenze only after Dressed has a catalog source and a vendor can demonstrate results on that same held-out set. ([Grounded SAM 2](https://github.com/IDEA-Research/Grounded-SAM-2); [Google Object Localization](https://docs.cloud.google.com/vision/docs/object-localizer); [Google Product Search](https://docs.cloud.google.com/vision/product-search/docs?hl=en); [RF-DETR export](https://github.com/roboflow/rf-detr/blob/develop/docs/exports/coreml.md))

**Privacy and operations are selection gates.** Google says online Vision images are processed in memory and not used to train Vision; AWS says Rekognition images may be used to improve its service unless the account opts out. Roboflow says Core-plan content may be used for product improvement or licensed datasets unless opted out, while Enterprise content is excluded. Confirm each chosen provider's retention, region, and opt-out terms before sending private closet photos; send only the needed crop, delete temporary queries on schedule, and keep catalog and service credentials behind Dressed's backend. ([Google Vision data usage](https://docs.cloud.google.com/vision/docs/data-usage); [AWS data use](https://docs.aws.amazon.com/rekognition/latest/dg/security-data-encryption.html); [Roboflow governance](https://roboflow.com/pricing))

## Conclusion

The first useful milestone is **reliable garment candidates plus human review**, not autonomous SKU identification. A detector can miss an obscured piece, and an excellent visual embedding still cannot find a product absent from the catalog. Dressed should decide how to obtain and maintain retailer data before buying an all-in-one matching service. Until identity evidence exists, the product should show visually similar alternatives and let the user confirm the item.
