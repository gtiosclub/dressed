# Build Dressed’s catalogue through approved sources

**Start with one retailer feed, not an autonomous crawler.** PacSun is the strongest first outreach target among the four named sources because its site links to an impact.com affiliate application, and impact.com supports partner product catalogues; PacSun-specific feed access and image rights still require acceptance and confirmation. ([PacSun affiliate link](https://www.pacsun.com/pacsun/); [impact.com catalogue guide](https://help.impact.com/partner/what-would-you-like-to-learn-about/platform-features/marketing-content/product-marketplace-and-catalogs/download-product-catalogs-as-a-partner)) Depop offers a private, seller-authorized API, which supports a later opt-in seller integration rather than a general marketplace catalogue. ([Depop authentication](https://partnerapi.depop.com/api-docs/concepts/authentication/); [Depop API reference](https://partnerapi.depop.com/api-docs/reference/)) No public Vinted listing feed or general Hollister product feed was verified in the official sources reviewed. An agent can help diagnose broken parsers, but fetching, validation, and publication should remain bounded and deterministic. Dressed already has the local import and search seam; its next engineering step is to put source permissions in trusted backend configuration before connecting any live source. ([Catalogue implementation](https://github.com/gtiosclub/dressed/blob/main/backend/catalog/catalog.py); [Catalogue spec](https://github.com/gtiosclub/dressed/blob/main/docs/catalog-and-recognition-spec.md))

## The four sources need different access paths

**PacSun: pursue partner catalogue access first.** Its site links to an impact.com affiliate application. impact.com can deliver brand product catalogues through its platform, FTP, or API, but brands control which partners can see a feed. That makes the application an access lead, not evidence that Dressed already has permission to import products or display images. Review the actual PacSun agreement, fields, update cadence, permitted display surfaces, and image use before building a live connector. PacSun’s published terms prohibit systematic collection and automated processes, so crawling public pages is a poor default route. ([PacSun site](https://www.pacsun.com/pacsun/); [impact.com partner catalogue guide](https://help.impact.com/partner/what-would-you-like-to-learn-about/platform-features/marketing-content/product-marketplace-and-catalogs/download-product-catalogs-as-a-partner); [impact.com brand catalogue guide](https://help.impact.com/brand/what-would-you-like-to-learn-about/platform-features/product-catalogs/add-product-catalogs-as-a-brand); [PacSun terms](https://www.pacsun.com/company/terms-of-use.html))

**Depop: consider consenting sellers as a separate product.** Its private Selling API needs partner approval; OAuth can authorize access to a seller’s own products, and product webhooks can be reconciled with periodic reads. The documented endpoint does not provide a general cross-seller search feed. Depop’s terms restrict scraping without express permission, while the API terms also restrict unapproved AI training uses. A seller opt-in integration would need explicit decisions about photo display, retention, and recommendation indexing. ([Depop first listing guide](https://partnerapi.depop.com/api-docs/getting-started/your-first-listing/); [Depop authentication](https://partnerapi.depop.com/api-docs/concepts/authentication/); [Depop webhooks](https://partnerapi.depop.com/api-docs/concepts/webhooks/); [Depop terms](https://depophelp.zendesk.com/hc/en-gb/articles/360001773148-Terms-of-Service); [Depop API terms](https://partnerapi.depop.com/api-docs/terms/))

**Vinted and Hollister: seek direct permission before automated import.** Vinted’s current US terms prohibit unauthorized scraping, crawling, and commercial reuse of site content; no official public catalogue feed was verified. Hollister promotes a creator Style Hub with personal storefronts and affiliate links, but that does not establish a general product feed. An accessible Hollister site-use page restricts copying and commercial display, although its current applicability could not be confirmed because the newer linked terms were not retrievable. For both, use Dressed’s reviewed user-shared link flow as the near-term feature, with editable details and no assumed live price, availability, or image reuse. ([Vinted US terms](https://www.vinted.com/terms-and-conditions); [Hollister Community](https://www.hollisterco.com/shop/us/br/Community?pagefm=navigation-footer); [Hollister Style Hub FAQ](https://community.hollisterco.com/account/faq); [Hollister site-use page](https://www.hollisterco.com/hol/site_use.html); [Dressed product scope](https://github.com/gtiosclub/dressed/blob/main/docs/product-scope.md))

## Agents should repair connectors, not roam websites

A crawler is an option only after a source expressly permits the relevant access, paths, rate, retention, and content use. **Robots rules do not grant authorization**, and public product markup does not grant a right to republish it. If a retailer permits crawling, configure fixed seed pages and allowed hosts and paths; cap requests and pages; check redirects and final destinations; use conditional requests where supported; and quarantine malformed or incomplete batches. An LLM should never choose arbitrary domains, bypass an access block, or invent missing product facts. ([RFC 9309](https://www.rfc-editor.org/rfc/rfc9309.html); [OWASP SSRF prevention](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html); [HTTP conditional requests](https://www.rfc-editor.org/rfc/rfc9110.html); [Dressed catalogue spec](https://github.com/gtiosclub/dressed/blob/main/docs/catalog-and-recognition-spec.md))

**Use an agent after a parser failure:** compare a small saved source sample with the last valid parse, draft a selector or field-mapping change, and explain the evidence. A developer reviews the change and runs fixture tests before promoting a new parser version. Keep the last valid catalogue state when required IDs, URLs, titles, or source fields disappear. This makes agent assistance useful without letting uncertain output become a published price or purchase link. ([Dressed catalogue spec](https://github.com/gtiosclub/dressed/blob/main/docs/catalog-and-recognition-spec.md))

## A PacSun pilot can reuse the current importer

**First, settle the source agreement.** Confirm whether PacSun grants Dressed a product feed, which products and fields it covers, permitted image use, retention, refresh, attribution and outgoing-link requirements. Pick one market and currency, a small category set, a product cap, and a request or cost ceiling. If the feed is unavailable, approach another participating retailer instead of substituting a PacSun crawler. ([impact.com catalogue guide](https://help.impact.com/partner/what-would-you-like-to-learn-about/platform-features/marketing-content/product-marketplace-and-catalogs/download-product-catalogs-as-a-partner); [PacSun terms](https://www.pacsun.com/company/terms-of-use.html))

**Then build the offline connector.** The existing Python importer validates feeds, generates stable IDs from source and external IDs, upserts changes, and ages out missing products only after complete successful scans. The current feed supplies its own approved host list, so move source ID, product and image hosts, acquisition method, and usage policy to trusted backend configuration before accepting live data. Convert a saved, authorized feed sample into the existing schema and mark partial or paginated slices incomplete. Add fixtures for duplicate IDs, bad URLs and redirects, invalid price, missing fields, and changed feed layout. Keep private `ClothingItem` records separate from public catalogue products. ([Catalogue implementation](https://github.com/gtiosclub/dressed/blob/main/backend/catalog/catalog.py); [Catalogue README](https://github.com/gtiosclub/dressed/blob/main/backend/catalog/README.md); [Catalogue spec](https://github.com/gtiosclub/dressed/blob/main/docs/catalog-and-recognition-spec.md))

**Finally run a bounded server-side pilot.** Hold credentials on the backend; limit pages, products, retries, and run frequency; record fetched, accepted, rejected, and changed counts; and quarantine failed batches. Compare a reviewed sample against source records for title, price, currency, stock, image, and final product URL. Require two repeat successful runs with stable IDs, no unapproved final hosts, no stale or unavailable results in search, and a demonstrated rollback to the last valid batch before widening coverage. Discovery Search already consumes the read-only catalogue API; a production service and freshness filtering remain separate work. The local `127.0.0.1` server is a prototype, not a deployable public service. ([Catalogue implementation](https://github.com/gtiosclub/dressed/blob/main/backend/catalog/catalog.py); [Catalogue README](https://github.com/gtiosclub/dressed/blob/main/backend/catalog/README.md); [Dressed catalogue spec](https://github.com/gtiosclub/dressed/blob/main/docs/catalog-and-recognition-spec.md))

## Conclusion

The first milestone should prove **one authorized, repeatable source**, not broad coverage. PacSun’s affiliate path is the best lead to investigate now; Depop is a later seller-consent integration, while Vinted and Hollister need direct access discussions. Once source rights and freshness are known, the existing importer offers a short path to a useful Discovery catalogue. Agent assistance becomes valuable when real feed or page changes create maintenance work; it should operate behind the reviewed connector rather than become the connector itself.
